# Security Guardrails

Rules no change may break. Each one protects a boundary described in the [security model](../architecture/security-model.md); if a feature seems to need one of them relaxed, raise it for discussion instead of working around it.

1. **Generated code runs only in runner pods.** AI-generated or user-authored project code executes only inside a live-preview Kubernetes pod, reached through the Kubernetes `exec` API — never in-process, never through a local shell. Compiling it there is the same rule kept: a turn's files are type-checked in a scratch folder of the project's preview pod (`CodeCheckServiceImpl`), never on a service's disk. Parsing it is not running it: `llm/SyntaxCheck` hands a written file to a parser as a string, in a JavaScript context with no host access, and must never evaluate it or build a script out of it.
2. **Code insight stays read-only by construction.** Its model gets at most one tool (`read_files`) - the step lesson, given the lines one step changed, gets none; its prompts never mention the `<file>` / `<todo>` / `<learn>` write protocol; and its tools are typed against the read-only `ProjectFileReader`. Don't add a write-capable tool, don't inline file contents into the prompt (the step lesson's bounded changed lines are the one exception, as a selection is for explain - and they are read from the caller's own saved turn, found by event id, project and user together, never taken from the request), and don't widen `ProjectFileReader`. A turn's big picture is not a second exception - it is given paths and reads through the tool - and neither are the project tour, a glossary entry and the check of a "try changing this" task: they are given file paths, a word or a task and read the files through the tool, so the check never has the file's text in its prompt, and the task sends the person to edit by hand but never offers the model a way to. The task itself is set from the same bounded changed lines, found the same way, as the step lesson (it counts as that exception, not a new one). The glossary's word is the one piece of free text from the browser to reach a model: it is cut to one line and 80 characters, goes in a user message and never the system prompt, and the model is told never to follow an instruction inside it. The reader's level stays an enum that picks a fixed paragraph, never free text.
3. **Replayed history is validated by value.** Any endpoint that replays client-supplied conversation history into a model must treat every role other than `"assistant"` as a user message, not just cap its length.
4. **`/internal/**` requires the internal-service authority.** Every filter chain keeps `requestMatchers("/internal/**").hasAuthority(...)` ahead of `anyRequest()`. Being authenticated is not enough — a user's session cookie authenticates on that path too.
5. **Filters are not accidentally global.** Spring Boot registers every `Filter` bean in the plain servlet chain. A new filter bean needs a disabled `FilterRegistrationBean` (as `InternalServiceAuthFilter` has) or should be constructed by the security chain that uses it instead of being a bean.
6. **Every project file path goes through `ProjectFilePath`.** Stored paths become ZIP entry names and preview-pod file paths, both of which resolve `..`. Never build an object key by string concatenation.
7. **CSRF stays on for cookie sessions.** The only exemptions are callers that structurally cannot send the header: the Stripe webhook and `/internal/**`.
8. **Permission guards sit where the caller is a user.** A service method also called from `/internal/v1` runs as a machine principal, so its user-permission guard belongs on the browser-facing controller. Conversely, every browser-facing path to a service method must be guarded.
9. **Frontend stores clear on sign-out.** A new module-level store with project- or user-specific data registers with `onSignOut(...)` in `frontend/src/lib/session.ts`.
10. **Secrets have no defaults**, and nothing that deploys enables `logging.level.org.springframework.ai.chat.client: DEBUG`, which logs every prompt and response in full.
11. **A published app is served only from its build's `site/` prefix, by a path checked first.** The proxy refuses a request path with a dot segment, a backslash, a NUL or a control character before it becomes a storage key, takes the content type from a fixed table by extension, and reads with a MinIO user that can read only `current.json` and `site/` files. Never build a storage key for a published app from a request path, a tar entry name or a link name without `ProjectFilePath` / `PublishedSlug` / `pathSegments` having accepted it first.
12. **Only the owner publishes, and taking an app down removes the pointer first.** The `PUBLISH` guard is on `PublishServiceImpl`, where the caller is a user. `<name>/current.json` is the one object the proxy serves from: unpublish and a project's deletion delete it before changing the row, so a storage failure leaves the app visibly published and the call repeatable.
13. **The one anonymous path is a `GET` under `/api/public/**`.** Any new anonymous endpoint needs a line in `app.security.public-get-paths` *and* a case in `FullChainPublishAccessTest` proving the other methods and look-alike paths stay behind a session. Every way a shared app can be unavailable answers the same "not found".
14. **What comes out of a build pod is untrusted data.** It is read through `util/TarArchive` (regular files only, links ignored, every name through `ProjectFilePath`, limits on count and size that raise rather than truncate), stored and served as bytes, never run or parsed on a service. A build runs only in a pod claimed for it, named on its row so the orphan sweep leaves it alone, and released afterwards.
15. **Published pages carry the strict headers and never a cookie.** Every published response, errors included, carries the headers in `proxy/published.js`; nothing in the published path reads or sets a credential. Environment files never enter the sources stored for the share page.
16. **A model's words reach the page only through `ChatMarkdown`.** It renders no raw HTML, fetches no image, and fences every link (`lib/safe-link.ts`). Don't render model text with `dangerouslySetInnerHTML`, a second Markdown renderer, or a plugin that passes HTML through.
17. **File text reaches a model only through `FileFence.guard`.** A file must not be able to print the marker line that ends its own fence. Anything new that shows a project file to a model fences it and guards it the same way.
18. **An invitation is not a membership.** Nothing reads `PROJECT_INVITE` to decide a permission, and inviting never asks account-service whether an address has an account. Don't add a lookup of users by email.
